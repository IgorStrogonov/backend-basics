# Стиль API Библиотеки

Этот документ описывает ключевые правила проектирования и оформления API для сервиса «Библиотека».

1. **Именование ресурсов (URL):** Используются существительные во множественном числе, в нижнем регистре (например, `/v1/books`, `/v1/readers`, `/v1/loans`).
2. **Разделители в URL:** Для составных названий используется `kebab-case` (например, `/v1/order-items`).
3. **Именование полей в JSON:** Используется `snake_case` (например, `full_name`, `available_copies`, `published_year`).
4. **Версионирование:** Версия API всегда указывается в URL (в нашем случае `/v1/`).
5. **Идентификаторы:** ID ресурса всегда передается в `path` (например, `/books/{id}`), а не в теле запроса или query-параметрах. Фильтры и сортировка — только в query.
6. **HTTP-методы:** Строго по назначению (GET — чтение, POST — создание, PATCH — частичное обновление, DELETE — удаление). Специфичные действия (например, возврат книги) реализуются через POST с глаголом в URL (`/loans/{id}/return`).
7. **Единый формат ошибок:** Все ответы с кодами 4xx и 5xx возвращают единый объект `ErrorResponse` с полями `code` (машиночитаемый код), `message` (человекочитаемое описание) и `details` (детализация по полям).
8. **Пагинация:** Для списков используются параметры `limit` и `offset`. Ответ всегда оборачивается в объект с полями `data` (массив) и `pagination` (метаданные).
9. **Идемпотентность:** Опасные операции POST (создание выдачи) требуют заголовка `Idempotency-Key` (UUID) для предотвращения дублирования при повторных запросах.
10. **Серверные поля:** Поля, которые вычисляются на сервере (например, `available_copies`, `id`, `registered_at`), помечаются как `readOnly: true` и не принимаются от клиента.
